# 밴드 공연 방명록 웹앱 설계

## 배경 및 목적

밴드 공연 당일, 관객이 QR/링크로 접속해 방명록을 남기고 서로의 글을 볼 수 있는
페이지를 하루 동안만 운영한다. 공연 중 무대 위에서 밴드가 그 시점까지 쌓인
글 중 하나를 실시간으로 무작위로 뽑아 보여주는 이벤트 기능이 핵심 요구사항이다.

- 운영 기간: 공연 당일 하루만
- 트래픽 규모: 공연 관객 수준 (수십~수백 건의 글 예상)
- 인프라 운영 부담을 최소화해야 함 (컴퓨터를 계속 켜둘 필요 없어야 함)

## 요구사항

1. 방문객은 이름, 전화번호 뒤 4자리, 메시지를 입력해 글을 남길 수 있다.
2. 방문객은 다른 사람이 남긴 글을 실시간으로(새로고침 없이) 볼 수 있다.
3. 목록에 표시되는 이름은 첫 글자만 남기고 나머지는 `x`로 마스킹하며,
   전화번호 뒤 4자리를 함께 표시해 본인/지인이 알아볼 수 있게 한다.
   - 전체 전화번호는 애초에 입력받지 않는다 (뒤 4자리만 수집).
4. 밴드는 별도의 관리자 페이지에서, 비밀번호 입력 후 그 시점까지의 전체 글
   목록을 볼 수 있고, "랜덤 뽑기" 버튼으로 무작위 글 하나를 뽑아 크게
   보여줄 수 있다. 표시 형식은 공개 화면과 동일한 마스킹 형식이되, 메시지
   전문을 읽을 수 있어야 한다.
5. 글 삭제/수정 등 별도 관리 기능은 불필요하다.
6. 관리자 페이지 비밀번호는 실수로 진입하는 것을 막는 수준이면 충분하다
   (고보안 요구 아님).

## 아키텍처

- **프런트엔드**: 정적 HTML/CSS/JS, Vercel에 무료 배포
- **데이터 저장/실시간 동기화**: Firebase Firestore (무료 티어), 브라우저에서
  Firestore SDK로 직접 읽기/쓰기 (별도 백엔드 서버 없음)

이 조합을 택한 이유: 정적 호스팅은 콜드 스타트가 없고, Firestore는 실시간
리스너를 기본 지원해 공연 중 "새 글이 바로바로 보여야 하는" 요구를 서버
운영 부담 없이 만족시킨다.

## 데이터 모델

Firestore 컬렉션 `entries`, 문서 필드:

| 필드 | 타입 | 설명 |
|---|---|---|
| `name` | string | 이름 전체 (예: "홍길동") |
| `phone4` | string | 전화번호 뒤 4자리 숫자 (예: "1234") |
| `message` | string | 방명록 메시지 |
| `createdAt` | timestamp (서버 시각) | 정렬/최신순 표시용 |

## 화면 구성

### `index.html` — 공개 방명록 페이지

- 작성 폼: 이름, 전화번호 뒤 4자리, 메시지 입력 → 제출 시 `entries`에 문서 추가
- 목록: `createdAt` 내림차순, `onSnapshot`으로 실시간 구독하여 새 글 자동 반영
- 목록 항목 표시: 마스킹된 이름 + 전화 4자리 + 메시지
  - 마스킹 규칙: 이름의 첫 글자만 남기고 나머지 글자 수만큼 `x` 반복
    (예: `홍길동` → `홍xx`). 2글자 성씨는 근사치로 첫 글자만 인식.

### `admin.html` — 관리자(밴드) 랜덤 뽑기 페이지

- 최초 진입 시 비밀번호 입력 프롬프트/폼. 통과 전에는 목록/버튼 비노출.
  - 클라이언트 측 문자열 비교로 충분 (보안 목적 아님, 실수 방지용).
- 통과 후: 실시간 전체 목록 표시 (공개 화면과 동일 마스킹 형식)
- "랜덤 뽑기" 버튼: 현재 로드된 목록에서 무작위 인덱스 선택 → 해당 항목을
  크게 강조 표시 (마스킹된 이름+전화4자리, 메시지 전문)

## 보안 및 검증 (Firestore Security Rules)

- `entries`: 누구나 `create`, `read` 허용
- `update`, `delete`는 전면 차단
- `create` 시 규칙 레벨 검증:
  - `name`: 비어있지 않은 문자열, 길이 상한(예: 20자)
  - `phone4`: 정확히 4자리 숫자로 구성된 문자열
  - `message`: 비어있지 않은 문자열, 길이 상한(예: 200자)
  - `createdAt`: 서버 타임스탬프 강제 (클라이언트가 임의 값 못 넣게)

## 에러 처리

- 폼 제출 시 필드 미입력/형식 오류(전화 4자리 형식 등)는 제출 전 클라이언트
  단에서 막고 안내 메시지 표시
- Firestore 쓰기/구독 실패 시 화면에 간단한 오류 안내 (재시도 유도)
- 관리자 페이지에서 글이 하나도 없을 때 "랜덤 뽑기" 버튼 비활성화 + 안내 문구

## 배포

1. Firebase 프로젝트 생성, Firestore 활성화, 웹 앱 등록 후 설정 키 발급
2. 위 Security Rules 배포
3. Vercel에 정적 파일 배포 → `https://<프로젝트명>.vercel.app` 링크 생성
4. 해당 링크를 QR코드 등으로 공연 당일 공유

## 테스트 방법

- 로컬 정적 서버(`npx serve`)로 여러 브라우저 탭을 열어 한쪽에서 작성 시
  다른 쪽에 실시간 반영되는지 확인
- 마스킹 함수: 짧은 이름(1글자), 2글자 성씨, 특수문자 포함 이름 등 경계
  케이스 수동 확인
- 관리자 비밀번호 게이트 동작 확인, 랜덤 뽑기가 매번 다른 결과를 낼 수
  있는지(완전한 균등 분포까지는 아니어도 편향 없이 동작하는지) 확인
- Vercel 배포 후 실제 URL에서 최종 통합 확인 (모바일 브라우저 포함)

## 범위 밖 (Out of scope)

- 글 수정/삭제, 신고, 욕설 필터링
- 회원가입/로그인, 전체 전화번호 수집
- 공연 이후 장기 운영, 커스텀 도메인
